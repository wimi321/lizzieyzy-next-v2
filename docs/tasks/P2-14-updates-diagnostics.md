## 目标

P2 第 5 批「发布」的后端：用户能从程序里检查并安装更新，出问题时能导出一个诊断包发给维护者，界面语言能在中文和英文之间切换。Java 参考在 `../lizzieyzy-next`，只学行为：`update/` 下的检查更新、`SignedUpdateEnvelope`、Windows 核心更新与回退；「帮助 → 诊断与日志」「停止完整日志」；「设置 → 语言」。

## 要做

1. **检查更新。**
   - 用 Tauri 官方的 updater 插件（`tauri-plugin-updater`），清单放在本仓库 GitHub Releases 的 `latest.json`；安装包用 updater 的签名（Ed25519/minisign）校验，公钥写进配置，私钥只在 CI 的 secret 里（本卡不生成真密钥，测试用测试密钥）。
   - 命令：检查（返回有没有新版本、版本号、发布说明、发布日期）、下载（进度事件、可取消；断点续传若插件不支持，失败后从头重来即可）、安装并重启。签名不对时拒绝安装并报错。
   - Windows 照插件的安装器流程；macOS、Linux 照 Java 的做法也可以：下载整包后打开所在位置，由用户替换（若插件能直接替换 `.app`/AppImage，用插件的）。无论哪种，用户的棋谱、设置和缓存不受影响，写测试证明设置目录不被动。
   - 启动时是否自动检查：保存在设置里，默认开，每天至多一次；不打扰正在进行的分析。
2. **诊断与日志。**
   - 日志用 `tracing` 写到应用数据目录下的滚动日志文件（大小上限），默认信息级别。
   - 「完整日志」：限时（例如 30 分钟，照 Java 的时长）把级别调到最详细，到时自动恢复；可以提前停止。
   - 导出诊断包：一个 zip，包括近期日志、设置（去掉任何账号、令牌和路径里的用户名之外的敏感信息照 Java 的脱敏规则）、引擎诊断（P2-12 的结果）、版本和系统信息；不包括棋谱内容。返回 zip 的路径，界面负责「打开所在文件夹」。
3. **界面语言。** 设置里加 `language`（跟随系统 / 中文 / English），读取和保存；Rust 侧凡是带文字返回界面的（例如引擎显示名的目录名）按这个语言。
4. 新字段、新命令照约定：生成的 TS 里可选，mock 补默认值，命令在 mock 里是脚本化的 `command`；下载进度用事件。

## 不做

- 签名证书、公证、正式发布流程：P2-15。
- 界面。

## 验收标准

1. 更新：用本地 HTTP 服务和测试密钥，覆盖有新版本、没有新版本、签名不对拒绝、下载取消、清单格式错误；设置目录不被安装流程改动。
2. 日志：滚动上限、完整日志到时恢复、提前停止，各有测试；诊断包内容有测试，并证明脱敏。
3. 语言设置的读写和默认值有测试。
4. 新依赖照规矩写一行理由；`docs/ARCHITECTURE.md` 更新。
