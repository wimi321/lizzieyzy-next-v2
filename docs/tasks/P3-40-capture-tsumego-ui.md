## 目标

P3 第 11 批的界面，用 P3-39 的命令和事件。Java 参考：
- `gui/CaptureTsumeGoFrame.java`：说明窗口、三步图示；
- `gui/CaptureTsumeGoSettings.java`：参数设置；
- 辅助程序 `CaptureTsumeGo1.2.jar` 的 `CaptureTsumego`：遮罩上的十字线、5×5 预览格、蓝框和黄色 / 品红预览点；
- `LizzieFrame.java` 18424–18450：开始和结束；
- `TsumeGoFrame.java` 35–44、265–275：死活题窗口里的「屏幕抓取」和 Shift+T。

## 要做

1. **入口**
   - 分析 → 抓取死活题(Shift+T)：打开说明窗口。
   - Shift+T：跳过说明直接开始。
   - 搜索功能能找到它（菜单项已有，接上绑定即可）。
   - 死活题对话框加「屏幕抓取」按钮：关掉死活题对话框，打开说明窗口。
2. **说明窗口**（照 Java）
   - 三个步骤，每步一张示意图（用 Java 的 `assets/capture1.png`、`capture2.png`、`capture3.png`）。
   - 下方：「参数设置」、提示「点错了可以按 Esc 取消」、「开始抓取(Shift+T)」。
3. **参数设置**：五个阈值，范围 0–255 / 1–100，越界或非整数时不能保存，并说明范围；可以恢复默认。
4. **开始之前**
   - 当前棋局有未保存的改动时，照「新建棋盘」的方式询问。
   - macOS 返回 `PermissionMissing` 时显示说明：需要在 系统设置 → 隐私与安全性 → 屏幕录制 里允许本应用。按钮有「打开系统设置」和「重试」；第一次缺权限时先调用 `request_capture_permission` 弹出系统询问。
   - `Busy`、`Unsupported`、截屏失败：在主窗口显示原因。
5. **抓取窗口**（`?window=capture`）
   - 截图铺满窗口，上面盖一层很淡的暗色，顶部一行用当前语言说明这一步要点哪里。
   - 点 1 之前：绿色十字线跟着鼠标。
   - 点 1 后：蓝色 5×5 预览格，格子大小随鼠标变化。
   - 点 2 后：蓝框从点 1 拉到鼠标，框里画网格。移动时请求 `recognize_capture`（只保留最新一次，最多每秒约 20 次），用黄点（黑子）和品红点（白子）显示识别结果。
   - 点 3 后进入确认：
     - 显示 列 × 行 和角；
     - 「棋盘大小」可选 9 / 13 / 19，默认是当前棋局的大小；放不下时自动改成能放下的最小一种，三种都放不下就不能确定；
     - 点预览里的交叉点，按 空 → 黑 → 白 循环修正；
     - 「确定」调 `finish_capture`；「重来」回到第一步；「取消」调 `cancel_capture`。
   - Esc 随时取消；Backspace 撤销上一次点击。
6. **结束后**：收到 `CaptureEnded`。
   - Finished：主窗口显示新棋局，自动打开死活题对话框（用已保存的选项）。
   - Cancelled：重新打开说明窗口（同 Java）。
   - Failed：显示原因。
7. **文案**：中文、英文；其他语言照现有做法用英文占位。

## 不做

- 后端（P3-39）。
- 自动找棋盘、识别轮走方。

## 验收标准

- Vitest：
  - 说明窗口和入口（菜单、Shift+T、死活题对话框里的按钮）；
  - 参数设置的范围检查和恢复默认；
  - 未保存改动的询问；权限说明的两个按钮；
  - 抓取窗口的三步、Backspace、Esc、识别请求只保留最新一次、修正循环、棋盘大小的默认值和放不下时的处理；
  - 结束事件的三种情况。
- Playwright：
  - 说明窗口一张基线；
  - 抓取窗口用一张测试里的棋盘图片（mock 返回）走完三步和一次修正，确认后主窗口打开死活题对话框，带一张确认阶段的基线；
  - macOS 权限说明。
- `scripts/verify.sh --e2e` 通过；`check_budgets.py` 通过（基线截图注意 1 MB 上限）。
- 真机：在这台 Mac 上用正式版抓取一张屏幕上的棋盘图片，识别、修正、确定后进入死活题；截主窗口的窗口图。
