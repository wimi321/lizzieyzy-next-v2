## 目标

把 P2-11、P2-12 的后端接到界面上，P2 第 4 批「引擎和设置」就此做完。入口照 Java 版放；样式标准见 ROADMAP 2026-11-11 的记录：布局和信息与 Java 版一致，观感不差于它。

## 要做

1. **引擎菜单。** 菜单栏的引擎菜单照 Java 列出所有引擎（「[1] 名字」…），勾选当前主引擎，点了切换；切换失败时提示原因、勾选回到原来的引擎。「重启当前引擎」「关闭引擎 → 关闭当前引擎」可用；关闭后状态栏能看出来，再选一个引擎就启动。
2. **设置 → 引擎。** 引擎列表：增、改、删、上移下移；改的时候沿用现有的引擎配置表单（程序、权重、配置、额外参数），保存时照现有流程试启动。
3. **设置 → 引擎规则。** 照 Java 的子菜单，勾选当前规则，点了保存并生效。
4. **综合设置。** 加读取棋谱贴目（关掉时可填默认贴目）、自动检测引擎是否存活、本地分析刷新间隔，照 Java 所在的分组。
5. **导入 Java 版配置。** 第一次启动时，如果在常见位置找到 Java 版的配置，提示一次可以导入；「设置」里也有入口。先显示预览（要导入的引擎、规则、显示设置，以及有问题的项），确认后写入。
6. **引擎一键设置。** 在现有的「性能优化」旁加上 Java 的「权重管理」「英伟达显卡提速组件」「概览」：
   - 权重管理：官方权重列表（名称、大小、日期、已下载），下载有进度和取消，下载好的可以设为当前主引擎的权重；
   - 提速组件：照后端给出的方案显示是否需要、下载安装和进度；
   - 概览：路径诊断的每一项和结果，有修复动作的给按钮，修复后重新诊断。
7. 移除 P2-11 为旧界面留的兼容层的使用（`settings.engine`、`configureEngine` 改用新接口）。

## 验收标准

1. 每个入口都有单元测试或 Playwright 测试：点了以后调用对应命令、界面随之变化；切换失败回退、下载取消、诊断修复后重新诊断各有测试。
2. Playwright 截图基线：引擎菜单、引擎列表、权重管理（下载中）、概览（有一项出错）、导入预览。
3. `scripts/verify.sh --e2e` 通过，`check_budgets.py` 通过。
