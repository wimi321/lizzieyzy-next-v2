## 目标

用真实应用加假引擎跑通主流程，作为以后每次改动的回归保障。

## 要做

- 用 tauri-driver（WebDriver）写测试，在 Linux 和 Windows CI 上运行。
- 测试准备：用 `--config-dir` 指向一个临时目录，写入指向 fake-katago 的引擎档案；通过启动参数打开一个语料棋谱。
- 流程：
  1. 启动后棋盘出现，候选点出现。
  2. 连按 → 20 次，候选点始终属于当前这一手：比对 DOM 上的当前手数和分析所属的手数。
  3. 点击胜率图跳转。
  4. 让引擎崩溃（fake 的 `--crash-after-ms`），状态灯变为 Restarting，再变为 Ready，分析恢复。
- macOS 没有官方的 WebDriver，不做，在汇报里说明。

## 验收标准

1. CI 的 e2e 任务在 ubuntu 和 windows 上都通过，总时长在 5 分钟以内。
2. 上面流程的每一步都有断言。过期结果在三层都会被过滤（协调器、app-core、前端 store），所以反向验证要三层一起关掉：在临时分支上关掉后跑 CI，E2E 必须失败（这个分支不合并）。
