## 目标

把 P3-15 和 P3-16 的后端接到界面上。入口照 Java 版放；样式标准照 ROADMAP 2026-11-11 的记录：布局和信息与 Java 版一致，观感不差于它。

## 要做

1. **同步 → 腾讯棋谱**：照现有的野狐棋谱窗口做。
   - 输入昵称或 UID，显示最近的查询（可清空）。
   - 表格：序号、时间、黑方（昵称和 UID）、段位、白方、段位、结果、手数、打开。查询的这个人赢的局用醒目的颜色。
   - 翻页，双击或点「打开」载入棋谱。
   - 「打开棋谱后此窗口」：最小化、关闭或不变。
   - 网络、超时、接口错误分别给出本地化的说明。
2. **文件 → 打开在线链接（Q）**：
   - 对话框打开时，如果剪贴板里是链接就预先填进去。
   - 失败时说明原因：不是 http/https、暂不支持弈客、不是棋谱、网络或超时。
3. **分析 → AI 解说，以及菜单栏的「AI 解说」按钮**：一个非模态窗口，照 Java 的 TeacherDialog 布局。
   - 顶部：模式（下一手、范围、整盘）和「设置」。
   - 上下文栏：下一手时显示当前手；范围时显示起止手。还有「开始解说」「停止」。
   - 两个页签：「解说」是边生成边显示的 Markdown，安全渲染；「分析依据」是发出去的依据原文。
   - 状态行：阶段（准备、生成中、核对中、完成、失败）、模型名、核对问题。
   - 底部：追问输入框和「追问」，「讲简单点」「为什么这样应」两个快捷按钮，「将解说加入棋谱评论」开关。
   - 没有配置服务时，「开始」变成「连接 AI」，打开设置。
4. **AI 解说设置**：
   - 服务地址，附常见服务的示例。
   - API key 输入框，可显示和隐藏，带「记住（存进系统钥匙串）」，并显示钥匙串是否可用。
   - 模型：可编辑的下拉框，「刷新模型」从服务读取列表。
   - 我的水平、风格、术语、详略、变化。
   - 一句隐私说明：会发给 AI 服务的是选中局面的棋盘和 KataGo 分析，足以还原局面；不发对局者名字、棋谱信息和评论。
5. **评论面板**：节点评论里的 AI 解说块单独显示在「AI 解说」标题下，和用户自己的评论分开；追问小节跟在后面。

## 验收标准

1. 每个入口都有单元测试或 Playwright 测试：点了以后调用对应的命令，界面随事件变化。
2. Playwright 截图基线：腾讯棋谱窗口（有结果）、打开在线链接的错误提示、AI 解说窗口（生成中和完成）、AI 解说设置、评论面板里的 AI 解说块。
3. 每个 Playwright 测试最多点开两层菜单，本地 1.3 秒以内（Linux CI 的 5 秒上限）。
4. `scripts/verify.sh --e2e` 通过，`check_budgets.py` 通过。
