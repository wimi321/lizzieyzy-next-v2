## 目标

维护者 2026-11-16 的反馈：底部工具栏的「远程算力」要默认显示，现在窗口一缩小就不见了。

原因：窗口宽度低于 1300 时，CSS 一律隐藏「远程算力」「更新官方权重」「自动播放」「设为主分支」（当初它们还是没做好的灰按钮），不管实际放不放得下。同时，固定的三栏网格在多数宽度下会让两边的按钮压到中间的导航按钮上（英文界面 1400 宽时就会）。

Java 参考：`gui/BottomToolbar.java` 380–475、5050–5160。导航组居中，两边放不下时挪开；左边先放主要按钮，其余能放就放；放不下的进溢出菜单。

## 要做

1. 按实际宽度排布底部工具栏，不再用固定的宽度断点：
   - 一直显示：「暂停分析 / 继续分析」「自动分析」、导航按钮、手数输入框和「跳转」。
   - 其余按钮按优先级占位，宽的放不下时，让后面窄的先放：
     - 远程算力
     - Kata形势
     - 坐标、手数
     - 删除、清空棋盘
     - 用户在自定义里打开的按钮
     - 更新官方权重、设为主分支
     - 自动播放（最先让位）
   - 导航组居中；两边放不下时往旁边挪，三组不重叠。
   - 界面语言、字号、按钮文字（例如自动分析的进度）变化时重新排布。
2. 放不下的按钮进「更多」菜单，按工具栏上的顺序排列，可用状态和按下状态照旧，点了照常执行。
   - 它们排在原有的「试下 / 终局点目 / 纯网络」之前，中间用分隔线隔开。
   - 原有三项都不显示时，「更多」只在有按钮放不下时出现。
3. 排布规则写成纯函数，单元测试。

## 不做

- 改变按钮的左右顺序和样式。
- 顶部工具栏。

## 验收标准

- Vitest：
  - 排布函数：宽窗口全部显示并居中；变窄时按优先级让位，「远程算力」最后；宽按钮让给后面的窄按钮；导航组挪开；「更多」只在需要时出现；固定按钮都放不下时左边优先。
  - 组件：窄窗口里「远程算力」留在工具栏上，放不下的进「更多」并能执行。
- Playwright：
  - 中文界面 1280、1100、900 宽时「远程算力」可见，三组不重叠，带一张 900 宽的基线；
  - 700 宽时从「更多」打开远程算力。
- `scripts/verify.sh --e2e` 通过；`check_budgets.py` 通过。
